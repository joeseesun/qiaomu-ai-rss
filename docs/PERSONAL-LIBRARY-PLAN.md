# 个人订阅、发现订阅与分组管理

状态：P1–P6 已完成，0.20.0 本地开发版已安装至 rockfish 并重载验证；尚未公开发布。基线 0.19.8；分支 codex/personal-library-discovery。
日期：2026-09-24。

## 产品目标与边界

用户从探索、手动地址、OPML、播客搜索、库内文件夹/笔记添加的来源，都属于本库的「我的订阅」。公共公众号目录继续提供完整发现能力；乔木精选只由已有编辑预设决定，个人添加、分组、目录更新不得写入公共精选。

三种任务：乔木精选阅读编辑选择；我的订阅阅读和管理自己的选择；发现订阅寻找新的来源。所有来源类型共享归属和管理界面，读取方式保持 RSS、远端播客、Vault Markdown 各自契约。

## 最终交互决策（后续讨论覆盖早期方案）

1. 频道选择器在「我的订阅」之后放 compass「发现订阅」，属于导航动作，不改变当前阅读频道、不显示频道勾选。
2. 顶部 + 直接打开发现订阅独立 Obsidian 页签并聚焦输入框。再次打开复用页签，保留分类、搜索和滚动位置，不显示六项添加菜单。
3. 我的订阅标题附近提供 list-tree 管理按钮。管理入口不放在 + 菜单。普通阅读状态不出现多选框。
4. 发现页只有一个输入框：搜索公众号、播客、博客，或粘贴 RSS/OPML 链接。名称走搜索；网址先识别 OPML/RSS，预览后确认添加。支持 GitHub blob OPML 链接转 raw。
5. 首页四入口：公众号、播客、独立博客、更多来源。下方「值得订阅」只显示 6 个人工推荐，混合博客、公众号、播客，具体推荐理由，不以目录收录冒充质量认证。
6. 718 来源数量只在更多来源页显示。全目录参与统一搜索，按 URL 去重，名称/简介/域名/主题匹配；结果分页，按类型/语言/主题渐进筛选。在线搜索失败与本地零结果分别显示。
7. 名称打开来源详情，显示简介与最近三篇文章/单集；只有主动预览才读取源。目录历史检测日期不等于当前可用。播客不承诺每期都有文稿。
8. 订阅成功保持当前位置、搜索和筛选；显示已订阅与阅读动作，用户主动阅读才跳转。
9. 次要入口：导入 OPML、添加本地内容。后者使用原生文件夹/笔记选择器。OPML 支持文件、XML 文本、在线地址，先预览，搜索/按组勾选，明确新增/重复/无效数量，重复不覆盖已有名称和分组。
10. 来源图标：明确头像/封面 → 真实网站 favicon → 汉字首字/字母。代理 Feed 不冒用代理商图标；库内来源使用文件夹/文件图标。缓存、有界请求、失败回退。
11. 文章正文 h1 可打开原文，三点菜单保留打开原文；本地笔记标题打开源笔记。列表文章标题仍负责阅读，避免误跳浏览器。

## 我的订阅与分组

单层分组，每个来源只归一个组。支持新建空组、重命名、排序（上下移动）、删除；删除组把所有类型来源移到未分组，绝不隐式取消订阅。未分组为虚拟组不可删改。来源支持改显示名、单个/批量移动、明确确认后取消订阅。取消本地来源不删除真实文件；收藏与笔记保留。

OPML 分组保留，嵌套路径保持「科技 / AI」显示；类型默认组只在需要时创建（微信公众号、播客、本地文件），用户可任意混合来源类型。组展开状态持久化；管理搜索名称、类型、路径与组名；分页避免数百行一次渲染。

阅读器频道树使用相同稳定分组 ID 与排序，所有个人来源都列入个人树。组聚合沿用 RSS 文章；播客和文件可在组内单独打开，混合组明确可选来源，避免为浏览导航遍历所有笔记和请求所有播客。

## 数据设计与可靠性

新增 libraryVersion、subscriptionGroups（id/name/order）、sourceMeta（按现有 source ID 映射 groupId/name/order）、collapsedGroups。
旧 subscriptions/group、followedPodcasts、markdownFolders 保持实际来源身份；统一 personalSources 适配器派生管理列表；所有添加入口统一登记元数据。组 ID 独立于名称，改名不破坏选择。RSS group 镜像用于旧版本和 OPML 兼容。

迁移在内存校验后进行，幂等；旧版数据先生成一次备份，成功持久化才运行。不能在 schema 解析失败时将默认空配置写回。未来不兼容 schema 拒绝写入。持久化串行；组变更失败恢复快照并反馈。订阅移除清理元数据；本地源重命名更新归属和路径。

批量导入上限提高到 2000，解析保留 5 MB 上限、拒绝 DTD/实体和非 HTTP(S) URL。导入不拉所有正文；聚合刷新每次最多 20 个较旧来源、最多 3 个并发，用户可继续刷新。新添加/来源独立刷新沿用显式触发。缓存总量受限，避免 2000 × 1 MB。

## Tidings 目录与来源归属

采用 https://github.com/fuxiaoai/tidings-rss 的固定提交 12fd5b826d15e97d0f4966782cc596336c0706be 的 data/feeds.json。CC0-1.0，仅使用目录元数据；商标/文章/产品截图不属于该授权。
内置 718 条快照支持离线检索，仓库 README 检查日期与数据内 validated_at 不一致，UI 以数据实际日期为准。分类包重叠按 feed URL 去重；不自动订阅，不合并到乔木精选。
提供显式更新目录操作，下载后结构/URL/数量校验再缓存，失败保留快照。仅更新发现目录，不增删个人来源。离线更新失败显示具体反馈。

## 移动端和无障碍

一套信息结构，发现页窄屏单列；四入口可换行，不裁切。Modal 最大高度使用可见视口，滚动区不遮挡主要动作；原生输入/选择控件、文件选择器。来源管理用点按与原生菜单，不依赖 hover、拖拽、长按、滑动手势。图标 18–20px、触摸命中区约 44px。使用可访问名称、focus-visible、Escape 与键盘遍历，无多余 tooltip、左侧装饰竖线或常驻说明。

## 开发顺序与验收计划

- P1 文档、schema、迁移、个人来源适配器、分组服务与失败回退测试。
- P2 我的订阅管理、来源树、发现导航、库内来源统一入口。
- P3 发现首页、混合搜索、来源预览、Tidings 快照与更新、分组选择。
- P4 在线 OPML/文件/文本导入、勾选筛选、规模限制与刷新预算。
- P5 favicon 回退、文章标题链接、窄屏和键盘细节。
- P6 lint/typecheck/单元测试/build；隔离桌面 host 交互检查；安装 rockfish，核对构建摘要、重载及 runtime。

关键回归：所有入口归属；分组改名不失效；删除组保留来源；OPML 重复不覆盖；718 项导入无隐式全量网络；关闭/切换后旧搜索不覆盖；favicon 失败回退；本地移除不删文件；我的订阅包含所有类型；乔木精选边界；标题与三点原文入口同时可用；独立发现页复用与状态保留。
桌面 host、窄屏模拟、iOS/Android 真机分开记录，不把模拟当真机。完成后更新本文件实施与验证记录。公开发布需另走发布门禁，当前先完成本地可测试版本。

## 讨论中既有问题的处理边界

- 公共公众号目录完整保留，目录规模会随服务变化；不把“有人订阅过”当作乔木精选入选标准。
- 乔木精选沿用基线已限定的编辑预设，包括李继刚、歸藏、AGENT橘、卡兹克、向阳乔木、晚点、elsewhere、赛博禅心等。此次个人分组、OPML 和目录更新均不修改预设。
- All-In 可在播客搜索中发现并添加至我的订阅，不加入乔木精选。搜索到节目不代表所有单集有转写；继续沿用基线的文稿、仅摘要和提取失败状态，本次不补造文稿。
- 收藏、已读、保存文章和实际笔记不因取消来源或删除分组而丢失。

### 规模与交互细节

大于 60 项的批量导入默认折叠涉及的命名组；用户仍可自行展开。发现每页 24 项、管理每页 60 项、个人文章每页 100 项。刷新每轮处理最久未尝试的最多 20 个来源，失败来源也记录尝试时间，避免持续阻塞其余来源。单请求超时 20 秒，订阅正文缓存总预算 20 MiB。

### 已知验证边界与后续发布

- 390px 是 Obsidian 桌面宿主的窄屏模拟；尚未在 iOS/Android 真机验证键盘、文件选择器和触摸行为。
- 在线来源和文稿受第三方可用性影响；目录历史检测不能保证当下质量或每期文稿完整。
- 个人分组可包含全部三类来源，OPML 导出遵循 RSS 格式，仅导出 RSS 来源；本地笔记和服务端播客不伪装成 RSS 地址。
- 下一发布阶段：完成用户本地体验反馈与手机真机检查，再执行发布资产、版本和公开安装验证。当前尚未创建公开 0.20.0 Release。
